# 📝 TODO-планировщик задач (Бэкенд-сервис)

Веб-сервис для управления списком дел и задач с возможностью планирования периодических событий. Проект выполнен в рамках итогового задания курса «Go-разработчик с нуля» от Яндекс Практикума.

---

## 📌 Описание проекта
Приложение представляет собой REST API бэкенд, работающий в связке с готовым фронтендом (статические файлы в папке `web`). 

**Основные возможности:**
* Создание, чтение, редактирование и удаление задач (CRUD).
* Поддержка правил повторения задач (`d` — дни, `y` — ежегодно, `w` — дни недели, `m` — дни месяца).
* Автоматический расчет следующей даты выполнения для периодических задач.
* Поиск задач по тексту (заголовок/комментарий) и по дате в формате `ДД.ММ.ГГГГ`.
* Защита API и веб-интерфейса с помощью авторизации по паролю и **JWT-токенов в Cookie**.

**Технологический стек:**
* **Язык:** Go 1.25+ (использован стандартный роутер `net/http` Go 1.22+).
* **База данных:** SQLite (драйвер `modernc.org/sqlite` без использования CGO для легкой кроссплатформенной сборки).
* **Аутентификация:** JWT (`github.com/golang-jwt/jwt/v5`), куки `token` со сроком жизни 8 часов.
* **Контейнеризация:** Docker / Docker Compose (Multi-stage build).

## ⭐ Выполненные задания повышенной сложности (со звёздочкой)
В проекте реализованы **все** задания повышенной сложности:

1. **Авторизация и безопасность (JWT)**:
   * Реализован эндпоинт `POST /api/signin` для аутентификации.
   * При успешном вводе пароля формируется JWT-токен (содержащий SHA256-хэш пароля) и записывается в Cookie `token` со сроком действия 8 часов.
   * Все ручки API защищены через `AuthMiddleware`.
   * Доступен встроенный интерфейс авторизации по адресу `/login.html`.
2. **Расширенный алгоритм `NextDate`**: полная поддержка сложных правил повторения задач (дни `d`, годы `y`, дни недели `w`, дни месяца `m`).
3. **Поиск и фильтрация**: поиск задач по фрагменту заголовка/комментария и фильтрация по конкретной дате (`ДД.ММ.ГГГГ`).
4. **Контейнеризация в Docker**: создан оптимизированный двухэтапный (`multi-stage`) `Dockerfile` на базе Alpine Linux и `docker-compose.yml` для удобного разворачивания.

## 🛠 Локальный запуск проекта

### Предварительные требования
* Установленный Go (версии 1.22 или выше).

### Настройка окружения
Создайте файл `.env` в корневой директории проекта (или скопируйте из примера):

```env
TODO_PORT=7540
TODO_DBFILE=scheduler.db
TODO_PASSWORD=123
JWT_SECRET=my_secret_key
```

> **Примечание:** Если переменная `TODO_PASSWORD` задана, приложение потребует ввод пароля при входе. Если оставить её пустой, авторизация будет отключена.

### Запуск приложения
Вы можете запустить проект несколькими способами:

1. **Напрямую через Go:**
   ```bash
   go run ./cmd/todo/main.go
   ```
2. **С помощью Makefile:**
   ```bash
   # Обычный запуск с переменными из .env
   make run

   # Запуск с явным указанием пароля
   make run-auth
   ```

### Доступ в браузере
* **Главная страница приложения:** 👉 [http://localhost:7540](http://localhost:7540)
* **Страница входа (если включен пароль):** 👉 [http://localhost:7540/login.html](http://localhost:7540/login.html)  
  *(Введите пароль, указанный в `TODO_PASSWORD`, например: `123`)*.

## 🐳 Сборка и запуск через Docker

### Вариант 1. Запуск через Docker CLI (Инструкция для ревьюера)

1. **Сборка Docker-образа:**
   ```bash
   docker build -t todo-app .
   ```

2. **Запуск контейнера с монтированием SQLite базы данных с хоста:**
   
   *Для Linux / macOS:*
   ```bash
   docker run -d \
     -p 7540:7540 \
     -v $(pwd)/scheduler.db:/data/scheduler.db \
     -e TODO_PASSWORD=123 \
     --name todo-server \
     todo-app
   ```

   *Для Windows (PowerShell):*
   ```powershell
   docker run -d `
     -p 7540:7540 `
     -v ${PWD}/scheduler.db:/data/scheduler.db `
     -e TODO_PASSWORD=123 `
     --name todo-server `
     todo-app
   ```

### Вариант 2. Запуск через Docker Compose

Для быстрого старта со всеми окружениями можно использовать `docker-compose`:

```bash
# Запуск в фоновом режиме со сборкой
docker-compose up --build -d

# Остановка контейнера
docker-compose down
```

После запуска контейнера приложение доступно по адресу:
👉 **[http://localhost:7540](http://localhost:7540)** (или **[http://localhost:7540/login.html](http://localhost:7540/login.html)**)
